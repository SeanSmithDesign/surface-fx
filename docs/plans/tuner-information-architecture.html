2 · The thesis — context is the filter

255 is mostly multiplexing, not 255 things on screen. The same logical dial is stored once per theme, per surface, per mode. So the job isn't "fit 255 sliders" — it's let context collapse 255 down to the ~15 that matter right now.

Those four selectors — surface, theme, active mode, selected layer — are the top-bar controls. They're not decoration; they're the mechanism that makes the panel small. Every one of your asks resolves through this:

Your ask How context answers it
Fewer panels Top-bar selectors replace whole panels of choices — theme/surface stop being panels, become filters.
Subfolders / nesting Already in the keys: domain → surface → group → param. We surface the tree, don't invent it.
Not there at all times Only the active mode's dials render (~4); the other 8 modes' 28 params stay hidden until you switch.
Imploding, not fixed Each group is a collapsible folder; theme collapses two dials into one "edit current theme."

4 · Proposed zones

Mapping the model onto the tool. Fewer, collapsible surfaces — driven by context.

Top bar Context & global

  • Surface / layer selector — disc, sheet (and future layers)
  • Theme toggle — decides which theme's values you edit
  • Mode picker — sets the active shader mode
  • Background isolate · Bake → site

Inspector The look

  • Collapsible folders: Layer · Envelope · Mode (active only)
  • reducedMotionSafe = true params live here (static appearance)
  • Advanced dials (e.g. mobileScale) collapsed by default

Motion The behavior

  • reducedMotionSafe = false params: springs, durations, speeds
  • The Direction-D trigger + envelope editor lives here
  • Per selected layer, matching its trigger

Rule Progressive disclosure

  • Only the active mode's params ever render
  • Theme = one dial editing the current theme (opt-in "edit both")
  • Folders remember collapsed/open state (localStorage, per Dialkit)
